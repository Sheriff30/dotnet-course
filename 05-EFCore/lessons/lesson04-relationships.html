المرحلة 5: Entity Framework Core

في درس SQL 7 عملنا العلاقات بالـ Foreign Keys. هنا هنعمل نفس الحاجة، بس بالـ Classes، و EF Core هو اللي هيعمل الـ Foreign Keys والـ JOINs لوحده.

الفكرة الجديدة: Navigation Property

في SQL، الكتاب فيه رقم الـ Category بس (CategoryId). في C#، تقدر كمان تحط الـ Category نفسها كـ Object جوه الكتاب:

public class Book
{
    public int Id { get; set; }
    public string Title { get; set; }

    public int CategoryId { get; set; }        // Foreign Key (number)
    public Category Category { get; set; }     // Navigation Property (the object)
}

كده تقدر تكتب book.Category.Name على طول، من غير ما تكتب JOIN.

الـ Propertyهي إيهفي الـ Database
CategoryIdرقمعمود Foreign Key حقيقي
CategoryObjectمش عمود. EF Core بيجيبه بـ JOIN

1. One-to-Many: Category فيها كتب كتير

public class Category
{
    public int Id { get; set; }
    public string Name { get; set; }

    public List<Book> Books { get; set; }      // all books in this category
}

public class Book
{
    public int Id { get; set; }
    public string Title { get; set; }

    public int CategoryId { get; set; }        // Foreign Key
    public Category Category { get; set; }     // this book's category
}
  • الـ Category فيها List، لأنها فيها كتب كتير.
  • الكتاب فيه Object واحد، لأنه ليه Category واحدة.
💡 EF Core بيفهم لوحده إن CategoryId هو الـ Foreign Key، لأن اسمه = اسم الـ Class + Id. وده اسمه Convention: لو سمّيت صح، مش محتاج تقوله حاجة.

والـ Migration هتعمل:

ALTER TABLE Books ADD CategoryId INT NOT NULL
    FOREIGN KEY REFERENCES Categories(Id);
CREATE INDEX IX_Books_CategoryId ON Books(CategoryId);
💡 فاكر في درس SQL 8 لما قلنا إن الـ Foreign Key مش عليه Index لوحده؟ EF Core بيعمله لوحده 👌

2. Many-to-Many بجدول وسيط: الاستعارات

زي جدول Borrowings في SQL: جدول وسيط فيه 2 Foreign Keys، وفيه بيانات زيادة (التواريخ). فبنعمله Class لوحده:

public class Borrowing
{
    public int Id { get; set; }
    public DateTime BorrowDate { get; set; }
    public DateTime? ReturnDate { get; set; }  // ? = can be null

    public int BookId { get; set; }
    public Book Book { get; set; }

    public int MemberId { get; set; }
    public Member Member { get; set; }
}

وفي Book و Member بتضيف:

public List<Borrowing> Borrowings { get; set; }
⚠️ DateTime?: علامة ? معناها إن القيمة ممكن تبقى null. والـ ReturnDate بيبقى null طول ما الكتاب لسه مرجعش. من غير ?، الـ DateTime مينفعش يبقى فاضي.

3. Many-to-Many من غير جدول وسيط: الـ Tags

لو الجدول الوسيط ملوش بيانات زيادة (بس BookId و TagId)، مش محتاج تعمله Class خالص. حط List في الناحيتين:

public class Book
{
    ...
    public List<Tag> Tags { get; set; }
}

public class Tag
{
    ...
    public List<Book> Books { get; set; }
}

و EF Core هيعمل الجدول الوسيط لوحده، بـ Composite Primary Key 🪄

4. One-to-One (نادرة)

زي عضو ليه بروفايل واحد بس. بتحط Object في الناحيتين (مش List)، والـ Foreign Key في واحد منهم. هنحتاجها قليل جداً، فكفاية تعرف إنها موجودة.
