Code-First هو الأشهر في المشاريع الجديدة: بتكتب Classes، و EF Core بيعمل الـ Database والجداول لوحده.

يعني إيه Migration؟

Migration = ملف C# فيه تغيير واحد في شكل الـ Database. زي الـ commit في Git، بس للـ Database.

  • أول Migration: اعمل جدول Books
  • التانية: ضيف عمود Genre لجدول Books
  • التالتة: اعمل جدول Members

بتتنفذ بالترتيب، فأي حد ياخد المشروع ويشغّلها، يطلعله نفس الـ Database بالظبط. وده هيفيدك بين الـ PC والماك: مش هتحتاج ملف setup.sql تاني.

1سطّب أداة الـ Migrations (مرة واحدة بس)

افتح PowerShell واكتب:

dotnet tool install --global dotnet-ef --version 10.*

اقفل الـ PowerShell وافتحه تاني، واتأكد:

dotnet ef

المفروض يطلعلك رسمة حصان 🦄 (شعار EF Core).

2بص على المشروع

ملف Book.cs:

public class Book
{
    public int Id { get; set; }
    public string Title { get; set; }
    public string Author { get; set; }
    public decimal Price { get; set; }
}

ملف LibraryContext.cs نفس الدرس اللي فات، بس الـ Connection String فيه Database=LibraryDb. الـ Database دي مش موجودة، و EF Core هو اللي هيعملها.

3اعمل أول Migration

روح لفولدر المشروع (اللي فيه ملف .csproj):

cd D:\dotnet-course\05-EFCore\exercises\Lesson03-Migrations\Lesson03-Migrations
dotnet ef migrations add InitialCreate

هيتعمل فولدر اسمه Migrations، وجواه ملف زي 20261114_InitialCreate.cs. افتحه:

protected override void Up(MigrationBuilder migrationBuilder)
{
    migrationBuilder.CreateTable(
        name: "Books",
        columns: table => new
        {
            Id = table.Column<int>(nullable: false)
                .Annotation("SqlServer:Identity", "1, 1"),
            Title = table.Column<string>(nullable: true),
            ...
        },
        constraints: table => { table.PrimaryKey("PK_Books", x => x.Id); });
}

protected override void Down(MigrationBuilder migrationBuilder)
{
    migrationBuilder.DropTable(name: "Books");
}

ده CREATE TABLE بس مكتوب بـ C# 😄 ولاحظ إن EF Core فهم لوحده إن Id هو الـ Primary Key وإنه IDENTITY.

Up()إزاي تطبّق التغيير
Down()إزاي ترجع فيه
⚠️ لحد دلوقتي مفيش حاجة اتعملت في الـ Database. ده مجرد ملف فيه الخطة.

4نفّذ الـ Migration

dotnet ef database update

دلوقتي EF Core:

  1. عمل Database اسمها LibraryDb
  2. عمل جدول Books
  3. عمل جدول __EFMigrationsHistory، وكتب فيه إن InitialCreate اتنفذت

افتح SSMS واعمل Refresh على Databases، هتلاقي LibraryDb 🎉

جدول __EFMigrationsHistory مهم: EF Core بيكتب فيه كل Migration نفّذها. فلما تشغّل database update تاني، بينفّذ الجديد بس.

5غيّر الـ Class

عايز تضيف عمود؟ متلمسش الـ Database. عدّل الـ Class واعمل Migration جديدة:

// ضيف السطر ده في Book
public int Pages { get; set; }
dotnet ef migrations add AddPages
dotnet ef database update

EF Core هيقارن الـ Classes بآخر Migration، ويعرف لوحده إن في عمود جديد، ويعمل ALTER TABLE Books ADD Pages INT 🪄

الدورة اللي هتكررها طول عمرك

  1. عدّل الـ Class
  2. dotnet ef migrations add اسم_واضح
  3. dotnet ef database update
💡 اختار أسامي واضحة زي AddPagesToBooks أو CreateMembersTable، عشان تفهم كل واحدة عملت إيه بعد شهور.

6الرجوع

الأمربيعمل إيه
dotnet ef database update InitialCreateيرجع لـ Migration معيّنة (بينفّذ Down() للي بعدها)
dotnet ef database updateيرجع لآخر Migration
dotnet ef migrations removeيمسح آخر Migration (لو لسه متنفذتش)
dotnet ef migrations listيعرض كل الـ Migrations
⚠️ قاعدة ذهبية: متعدّلش ملف Migration بإيدك بعد ما يتنفذ. لو عايز تغيّر حاجة، اعمل Migration جديدة.

💡 حاجة هتلاحظها

لو فتحت الجدول في SSMS، هتلاقي Title نوعه nvarchar(max) ومسموح يبقى NULL. ده لأننا مقلناش لـ EF Core إن العنوان إجباري ولا طوله كام. وده هنظبطه في الدرس 7.

✍️ التمرين: 5 أسئلة

اكتب إجاباتك في ملف answers.md اللي في المشروع:

  1. اعمل InitialCreate و database update، واتأكد من LibraryDb في SSMS.
  2. افتح ملف الـ Migration، واشرح بكلامك Up() و Down() بيعملوا إيه.
  3. ضيف Genre من نوع string لـ Book، واعمل Migration.
  4. اعمل Class جديد Member فيه Id و FullName و Email و JoinDate، وضيف DbSet<Member> Members في الـ Context، واعمل Migration.
  5. ارجع لـ Migration سؤال 3، وشوف جدول Members حصله إيه في SSMS، وبعدين رجّع لآخر واحدة.
💡 بعد كل Migration افتح ملفها وبص على اللي EF Core كتبه. دي أحسن طريقة تفهم بيها.
